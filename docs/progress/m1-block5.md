# M1 第五块：MCP + 审批（进度与拆分）

依据 PRD 的 FR-22、FR-23、FR-25、FR-27、FR-28，§9.6（MCP 连接器）、§9.7（治理层：审批、出站、审计），AC-06、AC-07、AC-08、AC-09、AC-11，演示剧本第 6、9、10、12 步；以及 decisions.md 的 D-12（治理层 P0）、D-03 第 3 条（MCP P0 只做远程，stdio 为 P1 且须沙箱）、D-21（资源 ACL + 审批流）、D-24（mcp-go）、D-27（审批超时一律按拒绝；是否审批只看平台策略）、D-33（审批人角色删除，改由审批策略配置）、D-38 第 9 条（MCP 出站日志写失败一律拒绝）。本块只做 P0：FR-24（stdio MCP）是 P1，FR-26（多级审批 / IM 推送）是 P2，均不在本块。

## 范围与技术要点

- **MCP 客户端**：`internal/mcp`，基于 `github.com/mark3labs/mcp-go`（MIT，D-24 选定；依赖 google/jsonschema-go BSD-3、google/uuid BSD-3、santhosh-tekuri/jsonschema Apache-2.0、spf13/cast MIT、yosida95/uritemplate BSD-3，均在许可白名单内，CI `go-licenses` 兜底）。传输方式：Streamable HTTP 与 SSE。HTTP 客户端**只用统一出站客户端** `egress.Client.HTTP()`，出站调用方标记 `module=mcp`，不声明 `AuditedFailClosed`（D-38 第 9 条：放行日志写失败即拒绝）。会话按需建立：每次发现 / 调用都是 initialize → 操作 → 关闭，带超时（默认 30 秒，可按服务器配置 5–120 秒）。
- **服务器登记**：`mcp_servers` 表（名称、URL、传输方式、超时、启用开关）。静态鉴权头用主密钥 AES-GCM 加密存储（与模型密钥同一主密钥，AAD 区分用途），接口只返回头名称、不回显值；主密钥轮换同时重加密 MCP 鉴权头。**端点不在出站白名单时禁止保存**（400，提示先加白名单），调用时仍以出站客户端的实时判定为准（含 DNS 解析后 IP 校验、元数据地址阻断）。
- **工具发现与目录**：发现到的工具写入 `tools` 表（key=`mcp:<server_id>:<name>`），**一律默认禁用**、默认「需审批」；按 MCP 注解给出**建议**风险等级（readOnlyHint → 只读；destructiveHint=false → 写入；其余 → 高危），由管理员确认（D-27：是否审批只由平台策略决定）。工具名称、描述、入参 schema 的哈希变化时标记「待复核」并自动禁用；服务端已下线的工具标记「已下线」并禁用。
- **工具治理（Policy Engine）**：每个工具设置风险等级（只读 / 写入 / 高危）、执行策略（自动 / 需审批 / 禁止）、审批人、审批超时、启用开关；工具 ACL 复用 `acl` 表（resource_type=`tool`，主体为成员 / 部门含下级 / 角色，`use` 位决定能否调用）。统一入口 `authz.ToolUsable` + `policy.Decide`：未启用、禁止、待复核、服务器停用、无 use 权限 → 对模型不可见；**高危工具不能设为自动执行**。
- **审批流**：`approvals` 表持久化**参数快照**（审批人看到的就是将要执行的原参数，不可修改）、对话上下文摘要、发起人、工具、审批人列表、到期时间。状态：待审批 → 通过 / 拒绝 / 超时 / 撤回；通过后用原参数执行**恰好一次**（状态条件更新保证）。超时一律按拒绝（D-27），到期判断在读取时实时生效，另有定期扫描落库。不可自批：发起人即使在审批人名单里也不能审批自己的单子。
- **对话中的工具调用**：会话可选择自己有权使用的工具（智能体在第六块接管绑定）。模型返回 tool_calls 后逐个经治理层：自动 → 执行；需审批 → 生成审批单，发出第三块预留的 `tool_call`（status=approval）与 `approval_pending` 事件，助手消息挂起为「等待审批」并持久化（服务重启后可恢复）；审批结束后由前端调用「继续」接口执行并把结果交回模型；拒绝 / 超时 / 撤回 / 禁止时把对应结果作为工具结果返回给模型。工具调用循环最多 5 步（超出安全终止）。
- **审计与 trace**：每次工具调用写 `tool.call` attempt（**写失败则不执行**，fail-closed）与 result；审批创建 / 通过 / 拒绝 / 撤回 / 超时都记审计；参数在审计中脱敏（按键名屏蔽 password / token / secret / key / authorization 等，并截断）；全部挂当前 trace_id，审批后的继续执行沿用原对话的 trace_id，保证一条链可还原（AC-11）。
- **前端**：管理后台「连接器」（列表 / 详情 / 发现工具 / 工具表格：风险、策略、启用、审批人、超时、授权）；「审批中心」（待我审批 / 我发起的；详情含完整参数 JSON 与对话摘要；通过 / 拒绝 + 意见；撤回）；对话页选择工具、工具调用卡片与审批卡片（轮询状态，审批结束自动继续）。
- **CI**：只用 mock 模型上游与本地假 MCP server（`cmd/mockmcp`，提供 `query_ticket` / `create_ticket`，并统计收到的调用次数，用于验证 AC-06「审批前服务端收到 0 次」），不读取任何真实密钥。

## 待确认（先按以下默认值实现，不阻塞开发）

1. **stdio MCP 不在本块**：用户需求里提到 stdio 进程隔离，但 PRD FR-24 与 D-03 / D-18 / D-24 把 stdio 定为 P1（须在隔离容器中运行），本块只做 P0，不实现 stdio 登记。备选：(a) 维持 P1，按 M1 P1 插入顺序排在 License 之后；(b) 提前到 M1 内做，需先定隔离方案（独立容器 + 无网络命名空间 + 经出站代理），工期约 1 周。
2. **MCP 鉴权头纳入主密钥轮换**：`mcp_servers.headers_enc` 与模型密钥同用平台主密钥加密（AAD 绑定服务器 ID），主密钥轮换时在同一事务中一并重加密；启动自检不因某个 MCP 头解不开而阻止启动（只影响该连接器的发现/调用，页面提示重新填写）。备选：(a) MCP 头单独一把密钥；(b) 解不开时阻止启动（与模型密钥一致，更严格）。
3. **schema 哈希包含工具描述**：哈希 = 名称 + 描述 + 入参 schema 的规范化 JSON；描述变化也触发「待复核 + 自动禁用」（描述会影响模型如何用工具，属于提示注入面）。备选：只哈希入参 schema（描述改动不打扰管理员）。
4. **下线工具的处理**：发现时缺失的工具标记 `removed` 并禁用，保留记录与授权（便于审计追溯）；重新出现后仍禁用、标「待复核」，需管理员重新确认。删除服务器才会连同工具与授权一起删除。备选：缺失即删除。
5. **发现时不信任工具注解决定执行方式**：注解只用于给出「建议风险等级」（readOnlyHint→只读，destructiveHint=false→写入，其余→高风险）；新工具一律禁用、需审批（D-27：是否审批只看平台策略）。备选：只读注解的工具默认「自动执行」。
6. **MCP 服务器地址必须在出站白名单内才能保存**，且每次发现/调用仍按实时白名单判定（白名单删除后立即失效）。备选：允许先保存、调用时再拦截。
7. **管理员不自动拥有工具使用权**：「可用」= 策略可用 且 ACL 有 use 位；超管/工具管理员也要显式授权（与 D-21 资源 ACL 一致，越权返回 404）。备选：工具管理员默认可用全部已启用工具。
8. **审批人为空时由本组织拥有「工具管理」权限的管理员审批**；审批人最多 20 人，须为本组织启用用户。备选：审批人为空时禁止设为「需审批」。
9. **审批超时**：可配 60 秒～7 天，默认 1800 秒；超时按拒绝处理（D-27）。备选：默认 10 分钟 / 24 小时。
10. **高风险工具不能设为「自动执行」**（保存时拒绝；历史数据若出现也按需审批处理）。备选：允许超管显式放开并记高风险审计。
