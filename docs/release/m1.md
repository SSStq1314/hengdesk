# 衡台 HengDesk M1 发布说明

本文记录第一个正式版（M1）的打包与验收约束。更细的安装步骤见 `docs/ops/offline-install.md` 与 `docs/demo/m1-acceptance.md`。

## 构建基线（D-48）

- M1 正式离线包必须基于 **`bf4d437` 或更新的提交** 构建（该提交合入了审计哈希链修复：detail 规范化与跨进程 advisory lock，PR #68）。
- 早于 `bf4d437` 的构建不得作为正式发布包。若演示或测试环境曾用更早的构建写过审计数据，**不要做旧链迁移**：清空数据库后重新初始化，再在新库上验收。
- 验收（15 步剧本、干净断网安装记录）必须在**新初始化的数据库**上进行。

## 审计哈希方案版本（D-48）

自本正式版起，审计哈希的规范化方式**不允许静默改变**。

- 当前基线为 **方案版本 1**，算法以 `bf4d437` 为准，说明见 `docs/dev/audit.md`。
- 此后若需调整入链字段、JSON 规范化或哈希算法，必须同时：
  1. 提升哈希方案版本号；
  2. 校验时按版本分别计算，或提供迁移；
  3. 在 `docs/dev/audit.md` 与后续发布说明中写明兼容策略。
- 未升版本就改变规范化，视为破坏审计链。

## 离线包

- 默认正式包：`./deploy/pack-offline.sh --version <版本>`，不含演示 mocks。
- 验收包（15 步剧本）：加 `--with-acceptance`，产物文件名带 `-acceptance`。
- 目标机使用 `install.sh --offline --up`，不要再 `docker pull` / `docker build`。

## 通义与 vLLM 冒烟（D-49）

- 通义真实冒烟**不再作为 M1 验收项**。M1 以按通义官方接口文档编写的契约测试，以及标明来源的录制回放代替。回放样本只能来自 vLLM CPU 小模型的真实录制，或通义官方文档里的示例，不允许凭空编造响应。
- dashscope 回放带已换成通义官方文档示例（`server/internal/gateway/testdata/dashscope_cassette.json`，来源与获取时间写在每条 `provenance`）。这不是通义真实调用，也不是 vLLM 实测。契约测试 `TestDashScopeCassetteProvenance` 与 `TestVendorContract*` 覆盖来源并走现有兼容层。
- vLLM CPU 小模型的真实协议冒烟**保留在 M1**，脚本与记录见 `docs/demo/vllm-cpu-smoke.md`，不进入断网 CI。
- D-46 第 8 条的正式包断网安装按 D-50 取证：GitHub 托管 x86 VM 上的默认正式包（无 mocks），只证明该云 VM。见 `docs/decisions/D-50-offline-install-evidence.md`。含 mocks 的 15 步不能代替。
- 在客户现场用客户自己的密钥做一次通义真实冒烟，写入 POC 交付手册 `docs/demo/poc-delivery.md`，不作为本仓库 M1 退出的离线门禁。
