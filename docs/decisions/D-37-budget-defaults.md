# D-37 预算与配额默认规则（产品经理定）

> 同步自 decisions.md（产品经理，2026-11-03，针对 PR #27 的 13 条待确认）。原文如下，实现说明附后。

工程提出 13 条默认规则，以下照原样采纳，或带修改采纳。

**照原样采纳**
- 1. Valkey 不可用时，有预算适用的调用返回 503。
- 2. 新建预算默认「超额拦截」，告警阈值默认 80%。
- 3. 部门预算包含所有下级部门，按调用人的主部门计入。
- 8. 同时跨过两档时只发 100% 那一条。
- 10. 告警接收人按工程方案。
- 12. 「按智能体」设预算放到智能体上线后。
- 13. 计数 15 分钟过期；修改预算后立即重建。

**修改后采纳**
- 4. 「测试连接」计入用量（保证用量 100% 覆盖），但**不受**超额拦截。超额时仍然能测试连接，方便排查问题。
- 5. 超时或上游 5xx 拿不到用量的记 0，但这条记录要标为「用量未知」，以便对账。流式中断时，有部分用量就按部分用量记账。
- 6. 周期按「系统时区」切分：可以配置，默认 Asia/Shanghai，不依赖容器的时区。只支持每日和每月。
- 7. M1 保持「调用前检查、调用后记账，不预扣」。预算页面上明确提示「并发或大请求可能少量超出」。另外把「严格模式」列为 P1：按 max_tokens 预扣额度，调用结束后多退少补，给要求严格不超预算的客户用。
- 9. 超级管理员和组织管理员都可以管理预算。部门管理员在 M1 可以**只读**查看本部门及下级部门的预算和用量，并接收告警。把「在上级预算额度内，由部门管理员给下级分配预算」列为 P1。
- 11. 告警去重：按「预算 + 周期 + 档位」把告警发送状态记在数据库里。重建计数后，同一档告警不重复发送；如果改了预算导致档位变化，则按新档位重新判断。

## 实现说明（M1 第二块 PR3b）
- 第 4 条：模型「测试连接」不再经过预算预检，照常写 usage_record（purpose=test）并结算进计数与告警。
- 第 5 条：`usage_records.usage_unknown`——调用失败且上游没有返回任何用量（超时、上游 5xx 等）时为 true，按 0 记账；
  用量汇总给出 `unknown_calls`，前端以「用量未知」标签标注。流式中断时网关附上已收到的部分用量，按部分用量记账，不标未知。
  迁移会把历史上「失败且 token 为 0」的记录回填为用量未知。
- 第 6 条：`HENGDESK_TIMEZONE`（IANA 名，默认 `Asia/Shanghai`）；二进制内置 tzdata，不读容器 `TZ`。无效时区启动失败。
- 第 7 条：预算页常驻提示「并发或大请求可能少量超出」。严格模式列入 P1。
- 第 9 条：新增权限 `budget.read`。超级管理员、组织管理员持有 `budget.manage` + `budget.read`；部门管理员持有部门范围的
  `budget.read`，只能看本部门及下级部门的部门预算、以及这些部门成员的个人预算（列表 / `GET /admin/budgets/:id`），
  范围外和所有写接口一律 404。组织管理员也接收告警。下级预算分配列入 P1。
- 第 11 条：新表 `budget_alert_states`（budget_id + period_key + level 唯一）。状态行、`budget.alert` 审计、站内提醒同一事务写入，
  审计写失败整体回滚、下次结算再试；不再依赖 Valkey 去重，计数重建后同档不重发。
  修改预算后按新级别重新判断：删除本期高于当前级别的状态，若当前级别尚未发过则立即补发。删除预算同时清理其状态。
- 第 13 条：新建 / 修改预算提交后立即以 `usage_records` 重建当期计数（不等下一次调用）。
