# D-40 对话：删除、保留、上下文与交互（产品经理定）

> 同步自 `decisions.md` 第 359 行起（产品经理，2026-11-03，针对 PR #33）。下面是原文，未作改写；实现说明在后面。

工程提出 9 条默认规则，以下照原样采纳，或带修改采纳。

**删除与保留**
- 1. **物理删除**：M1 不提供手动物理删除。用户删除会话仍是软删除，删除后对用户不可见。物理删除只通过第 2 条的保留期清理进行。「按人物理删除」列为 P1：用于响应个人信息删除请求，只有超级管理员可以操作，必须填写原因，记审计，受法律保留限制。
- 2. **对话消息保留期**：采用工程建议。
  - 默认不开启清理。
  - 开启后默认 365 天，最低 180 天。
  - 软删除的会话按同一保留期清理。
  - 清理记审计，内容包括操作人、时间范围、条数。
  - 法律保留可以按全组织或按用户设置；处于法律保留的数据不清理。
- 3. **审计内容**：同意。审计只记元数据，不记对话正文（PRD Q6）。

**上下文与计量**
- 4. 同意 M1 先固定取最近 50 条、单条上限 3.2 万字。PR3 补上按模型的 token 上下文截断：截断时总是保留系统提示词和最新一条用户消息。
- 5. 同意：用户停止生成后，已生成的部分计入用量，也作为下一轮的上下文。这条消息标为「已停止」。

**交互细节**
- 6. 生成失败时，用户的消息照样保留。**「重新生成」算 P0**，但只针对最后一条回复。旧回复软保留（审计可追溯），界面只显示最新一条。生成失败的消息直接显示「重试」按钮，效果等同于重新生成。
- 7. 同意：同一会话同时只允许 1 条在生成，否则返回 409，放进下一个 PR。
- 8. 同意每次发送都可以换模型，会话记住最后一次用的模型。如果记住的模型对用户已经不可用，就回退到默认模型并提示用户。

**D-39 遗留**
- 9. 同意：编辑白名单条目不会清除「待复核」标记，只有点「已复核」才清除。升级迁移遇到重复条目时合并，合并不放宽放行范围，并记审计。
