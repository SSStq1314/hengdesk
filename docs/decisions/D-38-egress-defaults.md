# D-38 出站控制默认规则（产品经理定）

> 同步自 decisions.md（产品经理，2026-11-03，针对 PR #28 的 10 条待确认）。原文如下，实现说明附后。

工程提出 10 条默认规则，以下照原样采纳，或带修改采纳。

**照原样采纳**
- 1. 升级时自动把现有模型上游的主机加入白名单，并记审计。补充：后台显示「升级自动添加的条目」，提示管理员复核一次。
- 2. OIDC issuer 主机按同样方式自动加入。
- 4. 拒绝范围过宽的 CIDR；云元数据地址必须单独写精确规则。
- 7. 网络层强制拦截列为 P1。部署文档中建议客户在防火墙侧配合。
- 8. 出站日志进入审计哈希链列为 P1。

**修改后采纳**
- 3. 端口列表为空时**默认只允许 443**；要允许任意端口，必须显式写 `*`，界面上给出风险提示。升级时自动添加的条目，使用上游 URL 里的实际端口。
- 5. 继续忽略系统代理环境变量。新增 P1：在平台设置中显式配置出站代理（企业内网常见需求）。走代理时，仍然按目标主机做白名单校验。
- 6. 不受白名单限制的范围，仅限部署配置里声明的数据库、Valkey、对象存储地址，不能扩大到任意内网地址。
- 9. 采用工程建议：只有调用方自己已经按 fail-closed 写过审计（目前只有模型网关），放行日志写失败时才继续放行；其他调用方（MCP、连接器等）放行日志写失败时，一律拒绝请求。调用方必须显式声明自己已写过审计，没有声明的按拒绝处理。被拒绝的请求，审计写失败时照样拒绝。
- 10. **改为留痕**：查看、筛选、导出出站日志都按敏感读取记审计，内容包括操作人、时间、筛选条件和导出条数，与 D-30 保持一致。

## 实现说明（PR4b）

1. **自动添加条目复核**：`egress_rules` 新增 `reviewed_at`、`reviewed_by`。来源为「升级迁移 / OIDC 自动」且未复核的条目在白名单页显示「待复核」徽标和顶部提示，管理员点「标记已复核」（`POST /admin/egress/rules/:id/review`，写 `egress.rule.review` 审计，fail-closed）；编辑条目也视为已复核。手动条目无需复核。
2. 未改动。
3. **端口**：空 = 仅 443；`*` = 任意端口（不能与具体端口混写），列表与编辑框显示风险提示。升级迁移 / OIDC 自动条目写入 URL 实际端口。
   **存量迁移**（只执行一次，`system_setting: egress.d38_ports`）：空端口的自动条目改为对应上游 URL 的实际端口（找不到对应上游时用 443）；空端口的**手动**条目改为 `*`，保持升级前的放行范围不变、不致业务中断，并在列表中以风险徽标提示管理员收窄。每条改动写 `egress.rule.ports_migrate` 审计（同事务）。
4. 未改动。
5. 继续忽略 `HTTP(S)_PROXY`；「平台设置中显式配置出站代理，走代理时仍按目标主机校验白名单」列入 P1（见 docs/progress/m1-block2.md）。
6. **基础设施豁免收窄到声明的地址**：对象存储客户端改用 `egress.InfraHTTP`，只能连接部署配置里的端点（未配置端点时为对应区域的 AWS S3 地址），不走代理、不跟随重定向；PostgreSQL 与 Valkey 只连接配置的 `DATABASE_URL` / `REDIS_ADDR`。
   `internal/egress/infra_test.go` 静态检查：数据库、Valkey、对象存储客户端只能在指定位置、用配置地址构造。
- 第 7、8 条：仍为 P1，未改动。
9. **调用方显式声明**：`egress.Caller.AuditedFailClosed`。出站前先写一条「放行 / 进行中」日志，结束后更新结果；放行日志写失败时，未声明的调用方直接拒绝（原因 `egress_log_unavailable`，并写 `egress.deny` 审计）。
   当前仅模型网关对话（`model.chat`，出站前已写 `model.call` 审计）声明；「测试连接」、OIDC 等均未声明。`TestOnlyGatewayDeclaresAuditedFailClosed` 防止其他模块私自声明。
10. **敏感读取留痕**：查看（无筛选）记 `egress.log.view`，带筛选记 `egress.log.filter`，导出记 `egress.log.export`；内容含操作人、时间、筛选条件、返回 / 导出条数。审计写失败返回 503，不返回数据。
    新增导出 `GET /admin/egress/logs/export`（CSV，按当前筛选，最多 10000 条，超出时响应头 `X-Export-Truncated: true`），权限与查看相同（`egress.log.read`）。

### 待确认（实现时的取舍）

- 存量**手动**空端口条目迁移为 `*`（而不是 443），以免升级后业务中断；是否改为 443？
- 导出沿用查看权限 `egress.log.read`，未单独设导出权限。
- 未接入出站日志的场景（单元测试、命令行工具）不写日志，照常放行。
- PostgreSQL / Valkey 的地址限制靠代码静态检查（只用配置地址），未在连接层另加拦截。
