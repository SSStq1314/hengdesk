# D-39 备用模型权限、切换记录、重试分类与出站收尾（产品经理定）

> 同步自 `decisions.md` 第 344 行起（产品经理，2026-11-03，针对 PR #30、#31）。下面是原文，未作改写；实现说明在后面。
>
> 更正：PR #32 首次合入时，这一节是工程按讨论记录整理的转述，不是原文。PR #33（对话 PR1）换成了原文，并逐条重新核对了实现，见文末「原文核对」。

工程提出 8 条默认规则，以下照原样采纳，或带修改采纳。

**照原样采纳**
- 4. M1 只靠静态检查，把数据库和 Valkey 的地址限制为配置里的地址。
- 7. 每个模型最多 3 个备用模型，重试次数和间隔用当前默认值。发生切换时，用量和审计记录**实际使用的模型**，并标注「由 A 切换」。

**修改后采纳**
- 1. 升级前手工添加、端口留空的条目，迁移后**只放行 443**，并标为「待复核」，和 D-38 保持一致。被模型上游引用的主机，按 D-38 第 1 条自动补上实际端口，所以模型不会断开。升级说明和后台都要提示「被拦截的出站请求」列表，方便管理员补规则。
- 2. M1 导出和查看共用一个权限，但导出必须记审计（D-38），且单次最多导出 10 万条。单独的导出权限列为 P1。
- 3. 单元测试可以不写日志。凡是真的会向外发请求的命令行工具，都必须写出站日志。
- 5. **读超时**不重试（上游可能已经开始计费）。**连接超时**和连接被拒绝时请求还没发出，可以重试，也可以切到备用模型。
- 6. 采用工程倾向的方案：只切到调用人有权限的备用模型；一个都没有时，返回原错误。配置备用模型的时候，如果它和主模型的可用人群不一致，界面上要给出提示。
- 8. 流式输出时，已经返回首个 token 就不再切换，直接把错误返回给调用方；首个 token 返回之前失败，按非流式规则重试或切换。

## 原文核对（PR #33）

按原文逐条对照了已合入的实现（main `4b26b39`）。结论：实现与原文一致，不需要改代码。

- 第 7 条「最多 3 个备用模型，重试次数和间隔用当前默认值」：与现有实现一致（`gateway.MaxFallbacks`，重试策略 `gateway.Retry` 未改）。
- PR #32 里有三处细节，原文没有逐字写到。核对结果如下，均保持现状：
  1. **连接建立后的其它中断不重试**：原文第 5 条只允许在请求还没发出时重试，理由是「上游可能已经开始计费」。连接建立后请求可能已经发出，不重试符合这条理由。
  2. **编辑条目不会清除「待复核」，只有点「已复核」才清除**：原文没有规定。现在的做法更保守，保持不变，列入待产品确认。
  3. **迁移后与已有条目重复时合并**：原文没有规定。合并后只放行 443 或上游的实际端口，没有放宽范围，并且每次合并都写审计，保持不变。
