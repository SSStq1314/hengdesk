# POC 交付手册

给在客户现场做 POC 的同事用。安装与 15 步剧本见 `docs/demo/m1-acceptance.md` 与 `docs/ops/offline-install.md`。不要把客户密钥、对话原文或未脱敏的日志带离现场，也不要写入本仓库、CI 或共享聊天。

## 通义真实冒烟（D-49，客户现场必做）

M1 仓库验收不再要求通义真实冒烟（没有通义密钥）。在客户现场交付时，必须用**客户自己的通义密钥**做一次真实冒烟，确认网关能连上客户环境里的通义兼容端点。

1. 由客户在其控制台创建或提供密钥，只注入现场环境变量（例如 `DASHSCOPE_API_KEY`），不要写入 `deploy/.env` 的提交副本、不要出现在日志和屏幕拍照里。
2. 在管理后台登记通义供应商（DashScope OpenAI 兼容模式，方言 `dashscope`），出站白名单放行客户实际使用的地域域名与端口。
3. 点「测试连接」，再在授权部门下用该模型走一轮非流式与流式对话，确认：
   - 能流式出字；
   - usage 已记账；
   - 配置查看与 API 响应中无密钥明文；
   - 错误（如错误 Key）被脱敏。
4. 只在交付记录里写：日期、客户环境（地域/是否内网）、模型名、非流式/流式是否通过。不粘贴密钥、不粘贴完整模型输出。
5. 冒烟结束后由客户撤销或轮换现场使用的临时密钥（若他们提供的是临时密钥）。

若客户暂不提供通义密钥，在交付记录写明「客户未提供密钥，通义真实冒烟未做」，并约定补测时间；不要用编造的响应或仓库里的回放带代替现场冒烟。
